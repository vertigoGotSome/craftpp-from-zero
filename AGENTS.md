# Project instructions

- Write repository content, comments, branch names, issues, pull requests and commits in English.
- Use `src/` for source, `tests/` for tests, `docs/` for documentation and `scripts/` for repository tooling.
- Use `main` as the default branch. Use NTLVD worktrees for task branches with `feature/`, `fix/`, `refactor/` or `docs/` prefixes and Conventional Commits.
- Keep diffs focused. Check for duplicates before filing substantial tasks.
- Run applicable checks and record their results. For native build changes, verify Debug and Release on x64. Run applicable tests when they exist.
- Document public APIs and non-obvious contracts. Evaluate Doxygen and use `@copydoc` where appropriate if adopted.
- Keep secrets, generated outputs and third-party reference material out of Git. Ask for authorization before publishing new public data or performing destructive operations.
- Capture substantial handoffs in `docs/HANDOFF.md`.
